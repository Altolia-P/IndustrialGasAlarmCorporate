## 四、架构与包结构

### 4.1 DDD 四层架构

```
Controller 层 (PublicController / AdminController)
    | 依赖 Service 接口
Service 层 (接口 + Impl)
    | 依赖 Assembler、Repository、领域对象
Assembler 层 (DTO 领域对象  VO 纯映射)
    |
Domain 层 (聚合根、值对象、Repository 接口、领域事件)
    | 实现
Infrastructure 层 (MyBatis-Plus Mapper/PO, Redis, Security, Config)
```

### 4.2 包结构

```
com.niit.industrialgasalarmcorporate
+-- common/
|   +-- base/          # Page, Result, BaseEntity
|   +-- exception/     # BusinessException 及其子类
|   +-- enums/         # ErrorCode 枚举
|   +-- utils/         # JWT工具, 日期工具等
+-- domain/
|   +-- model/         # 聚合根: Product, Content, Category, ContactMessage, User
|   |   +-- valueobject/ # ProductImage, ProductAttribute
|   +-- repository/    # Repository 接口
|   +-- event/         # DomainEvent, EventBus, 事件类
+-- application/
|   +-- service/       # Service 接口 + Impl
+-- assembler/         # ProductAssembler, ContentAssembler, CategoryAssembler, MessageAssembler
+-- interfaces/
|   +-- controller/    # PublicController, AdminController
|   +-- dto/           # 入参 DTO
+-- vo/                # 出参 VO
+-- infrastructure/
    +-- repository/
    |   +-- po/        # ProductPO, ContentPO, CategoryPO, MessagePO, UserPO 等
    |   +-- mapper/    # 继承 BaseMapper 的 Mapper 接口
    |   +-- impl/      # RepositoryImpl 实现
    +-- redis/         # RedisTemplate 封装
    +-- security/      # JWT 过滤器, 认证提供者
    +-- config/        # MyBatisPlusConfig, RedisConfig, SecurityConfig
```

## 五、领域模型核心

### 5.1 聚合根

| 聚合根 | 关键属性 | 领域方法 |
|--------|---------|---------|
| Product | productUuid, name, description, status, coverImage, images, attributes, categoryUuid | publish(), unpublish(), addImage(), addAttribute() |
| Content | contentUuid, title, body, coverImage, type, status, categoryUuid | publish() |
| Category | categoryUuid, name, type, parentUuid, sortOrder | - |
| ContactMessage | messageUuid, name, phone, content, ip, status, processor, remark, submittedAt, processedAt | markProcessed(processor, remark) |

## 六、数据库设计 (7 张表)

| 表名 | 主键 | 关键索引 |
|------|------|---------|
| t_category | category_uuid CHAR(36) | idx_category_type, idx_parent_uuid |
| t_product | product_uuid CHAR(36) | idx_product_category_status, uk_name |
| t_product_image | image_id BIGINT AUTO | idx_image_product_uuid |
| t_product_attribute | attr_id BIGINT AUTO | idx_attr_product_uuid |
| t_content | content_uuid CHAR(36) | idx_content_type_status, idx_content_category |
| t_contact_message | message_uuid CHAR(36) | idx_msg_status_submitted, idx_msg_phone_submitted, idx_msg_ip_submitted |
| t_admin_user | user_uuid CHAR(36) | uk_username |

设计约定:
- 所有表: deleted TINYINT(1) 逻辑删除, created_at/updated_at 审计字段
- 无物理外键, 逻辑引用
- UUID v4 CHAR(36) 主键

## 八、安全设计

- 密码: BCrypt 哈希存储 (passwordHash)
- 认证: JWT Token (含 userUuid + role)
- 登录锁定: 连续5次失败 -> 锁定30分钟
- JWT黑名单: Redis Set 存储
- 权限: 当前单一角色 ADMIN, role 字段预留扩展
- CORS: 仅允许官网域名
- 表单防刷: Redis 手机号60秒限制 + IP每分钟3次

## 十一、关键设计原则

1. DDD 四层架构: Controller -> Service -> Assembler -> Domain -> Infrastructure
2. Repository 返回 Optional
3. Assembler 纯映射, 不含业务逻辑
4. 聚合根封装业务规则, 内部收集领域事件
5. 审计字段自动维护 (MyBatis-Plus MetaObjectHandler)
6. 逻辑删除: 所有表加 deleted 字段
7. 无物理外键, 应用层保证关联完整性
8. MVP 优先, 避免过度设计
