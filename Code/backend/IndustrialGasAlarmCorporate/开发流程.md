# 后端开发流程

> 基于 DDD 四层架构 + Assembler，按依赖关系自底向上推进。

---

## 开发顺序总览

```
阶段1: common/          公共基础（Result、异常、错误码、JWT 工具）
阶段2: domain/           领域层（聚合根、值对象、Repository 接口）
阶段3: infrastructure/   基础设施（PO、Mapper、Config、Repository 实现）
阶段4: assembler/        装配层（DTO ↔ Domain ↔ VO）
阶段5: application/      应用层（Service 接口 + 实现）
阶段6: interfaces/       接口层（Controller → 公开 API + 后台 API）
阶段7: security/         安全层（JWT Filter、SecurityConfig）
阶段8: redis/            缓存层（防刷、黑名单、分类缓存）
```

每个阶段内按上下文独立开发，推荐顺序：**Category → Product → Content → Message → Auth**。

## 阶段 3：基础设施层 `infrastructure/`

### 3.1 配置 `config/`

| 序号 | 文件 | 说明 |
|------|------|------|
| 3.1.1 | `MyBatisPlusConfig.java` | 分页插件 `PaginationInnerInterceptor` + 乐观锁插件 `OptimisticLockerInnerInterceptor` + MetaObjectHandler（自动填充 `created_at`/`updated_at`） |
| 3.1.2 | `JacksonConfig.java` | 日期格式 `YYYY-MM-DD HH:mm:ss`、时区配置 |
| 3.1.3 | `CorsConfig.java` | 跨域配置 |
| 3.1.4 | `FileUploadConfig.java` | 文件上传：jpg/png/webp ≤5MB |

### 3.2 持久化 `repository/`

按上下文顺序，每个实体三件套：

```
infrastructure/repository/
├── po/       → 持久化对象（ @Getter @Setter, @TableName, @Version ）
├── mapper/   → MyBatis-Plus Mapper 接口（继承 BaseMapper<T> ）
└── impl/     → Repository 实现（注入 Mapper，完成 PO ↔ Domain 转换）
```

| 序号 | PO | Mapper | RepositoryImpl | 实现接口 |
|------|-----|--------|----------------|---------|
| 3.2.1 | `CategoryPO` | `CategoryMapper` | `CategoryRepositoryImpl` | `ICategoryRepository` |
| 3.2.2 | `ProductPO`, `ProductImagePO`, `ProductAttributePO` | `ProductMapper`, `ProductImageMapper`, `ProductAttributeMapper` | `ProductRepositoryImpl` | `IProductRepository` |
| 3.2.3 | `ContentPO` | `ContentMapper` | `ContentRepositoryImpl` | `IContentRepository` |
| 3.2.4 | `ContactMessagePO` | `ContactMessageMapper` | `MessageRepositoryImpl` | `IMessageRepository` |
| 3.2.5 | `AdminUserPO` | `AdminUserMapper` | `UserRepositoryImpl` | `IUserRepository` |
| 3.2.6 | `OperationLogPO` | `OperationLogMapper` | — | AOP 切面写入 |
| 3.2.7 | `SystemConfigPO` | `SystemConfigMapper` | — | 按需 |
| 3.2.8 | `EventOutboxPO` | `EventOutboxMapper` | — | AppService 内直接写入 |

> **PO 命名规则**：类名用 PO（全大写，如 `ProductPO`），对应表名 `t_product`。
> **PO 字段**：`@Getter` + `@Setter` 仅此两个注解，不用 `@Data`。
> **乐观锁**：`@Version private Integer version;` 在 PO 中声明，MyBatis-Plus 自动维护。
> **逻辑删除**：`@TableLogic private Integer deleted;` 需在 PO 中声明。

**验证标准**：每个 Repository 的 CRUD 通过集成测试。

## 开发顺序图

```
common/ ────────────────────────────────┐
domain/category ── domain/product ── domain/content ── domain/message ── domain/auth
     │                   │                  │                   │              │
     ▼                   ▼                  ▼                   ▼              ▼
infrastructure/category  infrastructure/product  infrastructure/content  infra/msg  infra/auth
     │                   │                  │                   │              │
     ▼                   ▼                  ▼                   ▼              ▼
assembler/category  assembler/product  assembler/content  assembler/msg  assembler/user
     │                   │                  │                   │              │
     ▼                   ▼                  ▼                   ▼              ▼
application/category  application/product  application/content  app/msg    app/auth
     │                   │                  │                   │              │
     ▼                   ▼                  ▼                   ▼              ▼
interfaces/public + interfaces/admin ← 所有 Controller 汇总
     │
     ▼
security/ + redis/ ← 最后配置，依赖所有上层就绪
```
