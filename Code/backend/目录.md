# ✅ 后端目录框架已初始化

基于 DDD 四层架构 + Assembler 模式，共创建 **33 个目录**，完整覆盖 `backend/`。以下是每层的详细介绍：

---

### 一、项目根路径

```
backend/IndustrialGasAlarmCorporate/
├── pom.xml                          → Maven 构建配置
├── src/main/java/com/niit/industrialgasalarmcorporate/
│   ├── common/                      ← 公共基础层
│   ├── domain/                      ← 领域层（纯业务）
│   ├── application/                 ← 应用层（业务编排）
│   │   ├── product/                 │   产品上下文
│   │   ├── content/                 │   内容上下文
│   │   ├── category/                │   分类上下文
│   │   ├── message/                 │   留言上下文
│   │   └── auth/                    │   认证上下文
│   ├── assembler/                   ← 装配层（对象转换）
│   ├── interfaces/                  ← 接口层（路由分发）
│   │   ├── public/                  │   公开 API
│   │   └── admin/                   │   后台 API
│   └── infrastructure/              ← 基础设施层
│       ├── repository/              │   持久化
│       │   ├── po/                  │     持久化对象
│       │   ├── mapper/              │     MyBatis-Plus Mapper
│       │   └── impl/                │     Repository 实现
│       ├── redis/                   │   缓存
│       ├── security/                │   安全
│       └── config/                  │   配置
└── src/main/resources/
    ├── application.yml              → 应用配置
    └── mapper/                      → MyBatis-Plus XML（可选）
```

---

### 二、`common/` — 公共基础层

全局共享的通用类和工具，**不依赖任何业务模块**：

| 待建文件 | 用途 |
|---------|------|
| `Result.java` | 统一响应体 `{code, message, data, success}` |
| `PageResult.java` | 分页响应 |
| `BusinessException.java` | 业务异常（含 `ErrorCode`） |
| `ErrorCode.java` | 错误码枚举 |
| `JwtUtil.java` | JWT 生成与校验 |
| `GlobalExceptionHandler.java` | `@ControllerAdvice` 全局异常处理 |

---

### 三、`domain/` — 领域层

**纯业务**，零框架注解（无 Spring、无 Lombok、无 Jackson）。放置聚合根和 Repository 接口：

| 待建聚合根 | 所属上下文 | 关键状态枚举 |
|-----------|-----------|------------|
| `Product` | product | `DRAFT` / `PUBLISHED` / `UNPUBLISHED` |
| `Content` | content | `SOLUTION` / `NEWS`（类型），`DRAFT` / `PUBLISHED`（状态） |
| `Category` | category | `PRODUCT_CATEGORY` / `CONTENT_CATEGORY` |
| `ContactMessage` | message | `PENDING` / `PROCESSED` |
| `User` | auth | — |

每个聚合根对应一个 Repository 接口（如 `IProductRepository`），定义在领域层，实现在基础设施层，遵循**依赖倒置**。

---

### 四、`application/` — 应用层

按业务上下文拆分为 5 个子包，每个子包内含 4 个子目录：

```
application/{context}/
├── dto/          → 接收前端参数的传输对象（如 ProductCreateDTO）
├── vo/           → 返给前端的视图对象（如 ProductVO）
├── service/      → 应用服务接口（如 IProductAppService）
└── service/impl/ → 实现类（编排业务流程 + @Transactional）
```

| 上下文 | 典型 DTO | 典型 VO |
|--------|---------|---------|
| `product/` | `ProductCreateDTO`、`ProductUpdateDTO` | `ProductVO`、`ProductDetailVO` |
| `content/` | `ContentCreateDTO`、`ContentUpdateDTO` | `ContentVO`、`ContentDetailVO` |
| `category/` | `CategoryQueryDTO` | `CategoryVO` |
| `message/` | `MessageSubmitDTO`、`MessageProcessDTO` | `MessageVO` |
| `auth/` | `LoginDTO` | `LoginResultVO`、`UserVO` |

**关键规则**：DTO 转 Domain、Domain 转 VO **必须通过 Assembler**，禁止在 Service/Controller 中直接用 `BeanUtils.copyProperties`。

---

### 五、`assembler/` — 装配层

纯对象映射，**不含任何业务逻辑**：

| 待建文件 | 职责 |
|---------|------|
| `ProductAssembler.java` | DTO ↔ Product(domain) ↔ ProductVO |
| `ContentAssembler.java` | DTO ↔ Content(domain) ↔ ContentVO |
| `CategoryAssembler.java` | DTO ↔ Category(domain) ↔ CategoryVO |
| `MessageAssembler.java` | DTO ↔ ContactMessage(domain) ↔ MessageVO |
| `UserAssembler.java` | DTO ↔ User(domain) ↔ UserVO |

---

### 六、`interfaces/` — 接口层

仅做三件事：**参数校验 → 调 Service → 返回 `Result<T>`**，不写 if/else 业务逻辑。

#### `interfaces/public/` — 公开 API（无需认证）

| 待建 Controller | 接口路径 |
|----------------|---------|
| `ProductController.java` | `GET /api/v1/public/products`（分页）、`GET /api/v1/public/products/{uuid}` |
| `ContentController.java` | `GET /api/v1/public/contents`（分页）、`GET /api/v1/public/contents/{uuid}` |
| `CategoryController.java` | `GET /api/v1/public/categories?type=` |
| `MessageController.java` | `POST /api/v1/public/messages` |

#### `interfaces/admin/` — 后台 API（JWT 鉴权）

| 待建 Controller | 接口路径 |
|----------------|---------|
| `ProductController.java` | CRUD + `POST /products/{uuid}/publish` + `POST /products/{uuid}/unpublish` |
| `ContentController.java` | CRUD + `POST /contents/{uuid}/publish` |
| `MessageController.java` | 分页查询 + `POST /messages/{id}/process` + `POST /messages/batch-process` |
| `AuthController.java` | `POST /admin/login`、`GET /admin/currentUser` |
| `CategoryController.java` | CRUD |
| `DashboardController.java` | 后台首页统计 |

---

### 七、`infrastructure/` — 基础设施层

#### `repository/po/` — 持久化对象

与数据库表一一对应，仅使用 `@Getter` + `@Setter`（不用 `@Data`，避免 toString 循环）：

| 待建 PO | 对应表 |
|---------|--------|
| `ProductPO.java` | `t_product` |
| `ProductImagePO.java` | `t_product_image` |
| `ProductAttributePO.java` | `t_product_attribute` |
| `ContentPO.java` | `t_content` |
| `CategoryPO.java` | `t_category` |
| `ContactMessagePO.java` | `t_contact_message` |
| `AdminUserPO.java` | `t_admin_user` |
| `OperationLogPO.java` | `t_operation_log` |
| `SystemConfigPO.java` | `t_system_config` |
| `EventOutboxPO.java` | `t_event_outbox` |

#### `repository/mapper/` — MyBatis-Plus Mapper

每个 PO 对应一个 Mapper 接口，继承 `BaseMapper<T>`。

#### `repository/impl/` — Repository 实现

实现 `domain/` 中定义的 Repository 接口，通过 Mapper 操作数据库。

#### `redis/` — 缓存层

按职责拆分，**没有统一的 RedisUtil**：

| 待建文件 | 职责 |
|---------|------|
| `MessageRateLimitRepository.java` | 留言频率限制（IP + 时间窗口） |
| `JwtBlacklistRepository.java` | 登出 Token 黑名单 |
| `CategoryCacheRepository.java` | 分类缓存 |
| `SystemConfigCacheRepository.java` | 系统配置缓存（含主动淘汰） |

#### `event/` — 事件层（V1.2 新增）

| 待建文件 | 职责 |
|---------|------|
| `EventOutboxService.java` | 事件发件箱写入/轮询投递（MVP 仅写入） |

#### `security/` — 安全

| 待建文件 | 职责 |
|---------|------|
| `JwtAuthenticationFilter.java` | `OncePerRequestFilter`，解析 Token 并设置 SecurityContext |
| `SecurityConfig.java` | `SecurityFilterChain`，配置接口权限 |
| `UserDetailsServiceImpl.java` | 加载用户信息 |

#### `config/` — 全局配置

| 待建文件 | 职责 |
|---------|------|
| `JacksonConfig.java` | 日期格式 `YYYY-MM-DD HH:mm:ss`、时区、Long 转 String |
| `CorsConfig.java` | 跨域配置 |
| `MyBatisPlusConfig.java` | 分页插件 + MetaObjectHandler（自动填充 `created_at`/`updated_at`） |
| `FileUploadConfig.java` | 文件上传配置（jpg/png/webp，≤5MB） |

### 八、数据流架构

```
 ┌──────────┐   ┌──────────────────┐   ┌──────────┐   ┌──────────────────┐
 │ 浏览器    │ → │ interfaces/      │ → │ common/  │ ← │ 统一响应 Result<T> │
 │ (Vue 3)  │ ← │ (Controller)     │ ← │ (Result) │   └──────────────────┘
 └──────────┘   └────────┬─────────┘
                         │ 调 Service 接口
                         ▼
 ┌──────────────────────────────────────────────────────┐
 │  application/{context}/service/                      │
 │    ┌──────────┐    ┌──────────────────────────────┐  │
 │    │ 接口 IXX │ ← │ impl: 编排 + @Transactional   │  │
 │    └──────────┘    └──────────┬───────────────────┘  │
 │                               │ 调 Assembler 转换     │
 │                               ▼                       │
 │  ┌────────────┐    ┌──────────────────┐              │
 │  │ assembler/ │ → │ domain/ 聚合根    │              │
 │  └────────────┘    └───────┬──────────┘              │
 │                            │ 调 Repository 接口       │
 └────────────────────────────┼─────────────────────────┘
                              │ 依赖倒置
                              ▼
 ┌──────────────────────────────────────────────────────┐
 │  infrastructure/repository/impl/                     │
 │                    ↓                                  │
 │       repository/mapper/ → PO → DB                   │
 └──────────────────────────────────────────────────────┘
```
