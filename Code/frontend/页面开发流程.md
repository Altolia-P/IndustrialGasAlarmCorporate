## 一、开发总流程

```
确认接口 → 检查类型 → 检查 API → 编写 Composables → 页面开发 → 组件抽取 → 验证
```

每一步具体做什么见下文。**每一步都是检查点**：类型/API 若已有则跳过，若缺失则先补齐。

## 二、单页面开发步骤模板

以"后台产品列表"为例，其他页面照此模式：

| 步骤 | 做什么 | 产出 / 参考文件 |
|------|--------|-----------------|
| 1. 确认接口 | 查阅 `接口文档(API).md`，明确 method、path、DTO、VO、分页/错误码 | `Doc/04_系统设计/4.接口设计文档/接口文档(API).md` |
| 2. 确认类型 | 检查 `types/{module}.ts` 是否已有 VO / DTO / 枚举 / 映射函数。若无则新增 | 已有：`product.ts`、`content.ts`、`message.ts`、`category.ts`、`auth.ts`、`common.ts` |
| 3. 确认 API | 检查 `api/{module}.ts` 是否已封装接口函数。若无则新增 | 已有：`product.ts`、`content.ts`、`message.ts`、`category.ts`、`auth.ts` |
| 4. 页面骨架 | 写 `views/` 页面：搜索区 + 数据区 + 分页区（后台列表页）或 展示区（前台页面） | — |
| 5. 接入 composables | 调 `usePagination()`、`useLoading()`、`useFormSubmit()` 等 | 已有：`composables/` 下 4 个 |
| 6. 接数据 | 调 API 函数获取数据，处理 loading / empty / error 三态 | — |
| 7. 接交互 | 编辑跳转、删除二次确认、上下架等操作 | — |
| 8. 样式 | Element Plus 组件 + scoped 样式，移动端 375px 适配 | — |
| 9. 验证 | `npm run lint` + `npm run dev` 浏览器查看 | — |

## 四、单页开发检查清单

每完成一个页面，检查以下项：

- [ ] loading 状态：数据加载中展示骨架屏/加载动画
- [ ] empty 状态：无数据时展示占位图 + 引导文案
- [ ] error 状态：接口异常时 Toast 提示，保留已填内容
- [ ] 列表分页：每页 20 条，页码从 1 开始
- [ ] 删除操作：二次确认弹窗
- [ ] 表单校验：所有字段前端校验 + 后端 4000 映射到字段标红
- [ ] 重复提交：按钮提交后 disabled
- [ ] 枚举展示：使用 `XxxMap` 映射函数，禁止 `status === 'PUBLISHED'`
- [ ] 响应式：375px ~ 1920px 适配
- [ ] `npm run lint` 零错误零警告
- [ ] 无 `any` 类型
- [ ] 无直接 `axios.get` / `localStorage` 操作
