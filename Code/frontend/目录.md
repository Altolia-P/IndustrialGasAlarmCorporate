## 三、路由层（1 个文件）

[src/router/index.ts](src/router/index.ts)

**前台路由**（`FrontLayout` 包裹，无需认证）：

| 路径 | 路由名 | 页面组件 |
|------|--------|---------|
| `/` | Home | 首页 |
| `/products` | ProductList | 产品列表 |
| `/products/:uuid` | ProductDetail | 产品详情 |
| `/solutions` | SolutionList | 解决方案列表 |
| `/solutions/:uuid` | SolutionDetail | 解决方案详情 |
| `/contact` | Contact | 联系我们 |

**后台路由**（`AdminLayout` 包裹，`meta.requiresAuth`）：

| 路径 | 路由名 | 页面组件 |
|------|--------|---------|
| `/admin` | AdminDashboard | 后台首页 |
| `/admin/login` | AdminLogin | 登录页（无需认证） |
| `/admin/products` | AdminProducts | 产品管理 |
| `/admin/products/create` | AdminProductCreate | 新增产品 |
| `/admin/products/:uuid/edit` | AdminProductEdit | 编辑产品 |
| `/admin/contents` | AdminContents | 内容管理 |
| `/admin/contents/create` | AdminContentCreate | 新增内容 |
| `/admin/contents/:uuid/edit` | AdminContentEdit | 编辑内容 |
| `/admin/messages` | AdminMessages | 留言管理 |

**路由守卫逻辑**：
- 访问 `requiresAuth` 页面但无 Token → 跳转 `/admin/login?redirect=原路径`
- 访问 `/admin/login` 但有 Token → 直接跳转 `/admin`
- 守卫实现在 `router/index.ts` 的 `beforeEach` 中

## 五、类型层（6 个文件）

严格遵循"前端只认 VO"规则，禁止出现 PO/Entity/Domain 等后端类型：

| 文件 | 定义内容 |
|------|---------|
| [src/types/common.ts](src/types/common.ts) | `Result<T>`、`Page<T>` 通用泛型接口 |
| [src/types/product.ts](src/types/product.ts) | `ProductVO`、`ProductDetailVO`、`ImageVO`、`AttributeVO`、`ProductStatus` 枚举 + 中文映射 |
| [src/types/content.ts](src/types/content.ts) | `ContentVO`、`ContentDetailVO`、`ContentType`/`ContentStatus` 枚举 + 中文映射 |
| [src/types/category.ts](src/types/category.ts) | `CategoryVO`、`CategoryType` 枚举 + 中文映射、`children` 树形结构 |
| [src/types/message.ts](src/types/message.ts) | `MessageVO`、`SubmitMessageDTO`、`ProcessMessageDTO`、`MessageStatus` 枚举 + 中文映射 |
| [src/types/auth.ts](src/types/auth.ts) | `LoginDTO`、`LoginResultVO`、`UserVO` |

> 每个枚举都配了 `XxxMap` 映射函数（如 `ProductStatusMap`），禁止在组件中硬编码 `status === 'PUBLISHED'`。

## 六、API 层（5 个文件）

与《接口文档(API).md》的 21 个接口一一对应：

| 模块 | 文件 | 覆盖接口 |
|------|------|---------|
| `authApi` | [src/api/auth.ts](src/api/auth.ts) | `POST /admin/login`、`GET /admin/currentUser` |

| `contentApi` | [src/api/content.ts](src/api/content.ts) | 前台 2 个 + 后台 5 个（CRUD + publish） |

## 七、状态管理层（1 个文件）

[src/stores/auth.ts](src/stores/auth.ts) — Pinia Store

| 状态 | 类型 | 说明 |
|------|------|------|
| `token` | `ref<string\|null>` | 当前 JWT Token |
| `userUuid` | `ref<string>` | 当前用户 UUID |
| `username` | `ref<string>` | 当前用户名 |
| `isLoggedIn` | `computed` | 计算属性，判断是否已登录 |
| `loginSuccess()` | 方法 | 登录成功后存储 Token + 用户信息 |
| `logout()` | 方法 | 退出登录，清除全部状态 |

> Pinia 只存认证状态，不存列表/分页/表单数据。页面级数据在组件内用 composables 管理。

## 十二、启动方式

```bash
# 1. 安装依赖
cd frontend
npm install

# 2. 启动开发服务器（默认 http://localhost:5173）
npm run dev

# 3. 生产构建
npm run build

# 4. 预览构建产物
npm run preview
```

> **注意**：首次启动前确保已执行 `npm install` 生成 `node_modules`。若安装被中断导致 `ERR_MODULE_NOT_FOUND`，需清理后重装：`rd /s /q node_modules && del /f package-lock.json && npm install`。
