## 一、系统环境

### 1.1 服务清单

| 服务 | 端口 | 用途 | 启动方式 |
|------|------|------|---------|
| MySQL 8.0 | 3306 | 关系数据库（app 库 + collector 库） | Docker / 系统服务 |
| Redis 7.x | 6379 | 缓存 + Token 黑名单 | Docker / 系统服务 |
| RabbitMQ | 5672/15672 | 设备事件消息队列 | Docker / 系统服务 |
| Nacos | 8848 | 服务注册与配置中心 | 独立进程 |
| Spring Boot (app) | 8080 | 后端 API 主服务 | `java -jar app.jar` |
| Spring Boot (collector) | 8081 | 设备数据采集微服务 | `java -jar collector.jar` |
| Vue 3 (开发) | 5173 | 前端开发服务器 | `npm run dev` |
| Nginx (生产) | 80/443 | 反向代理 + 静态文件 | 系统服务 |

### 1.2 目录结构

```
~/project/
├── backend/

├── sql/

```

## 二、日常运维

### 2.1 每日检查清单

| 检查项 | 命令/方式 | 预期结果 |
|--------|----------|---------|
| MySQL 运行状态 | `systemctl status mysql` 或 `docker ps` | running |
| Redis 运行状态 | `redis-cli ping` | PONG |
| 后端运行状态 | `curl http://localhost:8080/actuator/health` | `{"status":"UP"}` |
| 磁盘空间 | `df -h` | 使用率 < 80% |
| 内存使用 | `free -h` | 可用 > 500MB |
| 应用日志异常 | `tail -100 logs/error.log` | 无新增 ERROR |

### 2.2 服务启动/停止

```bash
# === MySQL (Docker) ===
docker start mysql8
docker stop mysql8

# === Redis (Docker) ===
docker start redis7
docker stop redis7

# === Spring Boot ===
# 启动
nohup java -jar app.jar --spring.profiles.active=prod > logs/app.log 2>&1 &
# 停止
kill $(cat app.pid)

# === Nginx ===
sudo systemctl start nginx
sudo systemctl stop nginx
sudo systemctl reload nginx   # 热重载配置
```

### 2.3 日志查看

```bash
# 应用日志（最近 100 行）
tail -100 logs/app.log

# 实时跟踪
tail -f logs/app.log

# 搜索错误
grep "ERROR" logs/app.log | tail -20

# 搜索特定用户操作
grep "admin" logs/app.log | tail -20

# Nginx 访问日志
tail -100 /var/log/nginx/access.log
```

## 三、监控告警

### 3.1 健康检查端点

| 端点 | 用途 |
|------|------|
| `GET /actuator/health` | 综合健康状态 |
| `GET /actuator/health/db` | 数据库连通性 |
| `GET /actuator/health/redis` | Redis 连通性 |
| `GET /actuator/metrics` | 应用指标 |

### 3.2 关键指标

| 指标 | 告警阈值 | 说明 |
|------|---------|------|
| 设备离线数 | > 总设备 30% | 可能网络故障 |
| PENDING 告警数 | > 50 | 积压需人工介入 |
| Token 过期率 | 突增 | 可能时钟不同步 |
| 登录失败率 | > 10% | 可能暴力破解 |
| 磁盘使用率 | > 85% | 需清理日志或扩容 |

### 3.3 告警记录查询

```sql
-- 当前所有未处理告警
SELECT a.alert_uuid, d.name, a.severity, a.message, a.triggered_at
FROM t_alert a JOIN t_device d ON a.device_uuid = d.device_uuid
WHERE a.status IN ('PENDING', 'CONFIRMED')
ORDER BY a.severity DESC, a.triggered_at DESC;

-- 近 24 小时告警统计
SELECT severity, COUNT(*) AS cnt
FROM t_alert
WHERE triggered_at > DATE_SUB(NOW(), INTERVAL 24 HOUR)
GROUP BY severity;
```

## 四、备份与恢复

### 4.1 数据库备份

```bash
# 全量备份
mysqldump -u root -p industrial_gas_alarm_corp \
  > backup/backup_$(date +%Y%m%d_%H%M%S).sql

# 仅备份结构（不含数据）
mysqldump -u root -p --no-data industrial_gas_alarm_corp \
  > backup/schema_$(date +%Y%m%d).sql

# 定时备份（crontab，每天凌晨 2 点）
0 2 * * * /path/to/backup.sh
```

### 4.2 数据库恢复

```bash
# 恢复全量备份
mysql -u root -p industrial_gas_alarm_corp < backup/backup_20260601_020000.sql

# 重新初始化（清空所有数据，仅保留表结构）
mysql -u root -p -e "DROP DATABASE industrial_gas_alarm_corp; CREATE DATABASE industrial_gas_alarm_corp;"
mysql -u root -p industrial_gas_alarm_corp < sql/Gas-ToB-SQL.sql
mysql -u root -p industrial_gas_alarm_corp < sql/demo-data.sql
```

### 4.3 Redis 备份

```bash
# Redis 默认自动 RDB 持久化，检查配置
redis-cli CONFIG GET save
# 输出: save 900 1 300 10 60 10000

# 手动触发备份
redis-cli BGSAVE
# 备份文件位置
ls /var/lib/redis/dump.rdb
```

## 五、常见问题排查

### 5.1 后端无法启动

| 现象 | 可能原因 | 解决 |
|------|---------|------|
| `Connection refused` | MySQL/Redis 未启动 | `docker ps` 检查容器 |
| `Access denied for user` | 数据库密码错误 | 检查 `application-prod.yml` |
| `Port 8080 already in use` | 端口被占用 | `lsof -i :8080` → kill |
| `OutOfMemoryError` | JVM 堆内存不足 | `java -Xmx512m -jar app.jar` |
| `Table doesn't exist` | 未执行建库脚本 | 执行 `Gas-ToB-SQL.sql` |

### 5.2 前端白屏/加载失败

| 现象 | 可能原因 | 解决 |
|------|---------|------|
| 白屏 | JS 报错 | F12 查看 Console 错误 |
| API 请求 401 | Token 过期 | 重新登录 |
| API 请求 CORS 错误 | 跨域配置问题 | 检查后端 CORS 配置 |
| 图片不显示 | 路径错误 | 检查 Nginx `try_files` 配置 |

### 5.3 设备数据不上报

| 现象 | 可能原因 | 解决 |
|------|---------|------|
| 设备 OFFLINE | apiToken 错误 | 检查 Header `X-API-Token` |
| 数据点不入库 | 时间格式错误 | 使用 ISO 8601 格式 |
| 告警不触发 | 规则 disabled | `SELECT * FROM t_alert_rule WHERE enabled=1` |

### 5.4 Token 相关问题

| 现象 | 原因 | 解决 |
|------|------|------|
| 频繁要求重新登录 | accessToken 过期（30min） | 前端自动 refresh |
| refresh 失败 | refreshToken 已过期/被吊销 | 重新登录 |
| 登出后仍可访问 | Token 未加入黑名单 | 检查 Redis `blacklist:*` key |

## 六、性能优化

### 6.1 数据库优化

```sql
-- 检查慢查询
SHOW VARIABLES LIKE 'slow_query%';
SHOW VARIABLES LIKE 'long_query_time';

-- 分析表（定期执行）
ANALYZE TABLE t_device_data_point;

-- 查看索引使用情况
EXPLAIN SELECT * FROM t_device_data_point 
WHERE device_uuid = 'xxx' AND recorded_at > '2026-05-01';
```

### 6.2 Redis 优化

```bash
# 查看内存使用
redis-cli INFO memory | grep used_memory_human

# 查看黑名单 key 数量
redis-cli DBSIZE

# 清理过期 key（Redis 自动，但可手动触发）
redis-cli --scan --pattern "blacklist:*" | xargs redis-cli DEL  # 慎用！
```

### 6.3 JVM 调优

```bash
# 推荐生产参数
java -jar app.jar \
  -Xms256m \           # 初始堆
  -Xmx512m \           # 最大堆
  -XX:+UseG1GC \       # G1 垃圾回收
  -XX:MaxGCPauseMillis=200 \
  -Dspring.profiles.active=prod
```

## 七、安全管理

### 7.1 定期操作

| 频率 | 操作 | 命令 |
|------|------|------|
| 每月 | 修改数据库密码 | `ALTER USER 'app'@'%' IDENTIFIED BY 'new_password';` |
| 每月 | 清理过期 Token 黑名单 | Redis 自动 TTL 过期，无需手动 |
| 每季度 | 审查管理员账号 | `SELECT username, role, last_login_at FROM t_admin_user;` |
| 每季度 | 检查 JWT Secret 强度 | 确认 ≥ 256 bit |

### 7.2 安全加固清单

- [ ] 生产环境关闭 `/actuator` 公网访问（仅 localhost）
- [ ] MySQL 禁止远程 root 登录
- [ ] Redis 设置密码 `requirepass`
- [ ] Nginx 配置 HTTPS + HSTS
- [ ] 限制 API 调用频率（Nginx `limit_req` 或 Redis 滑动窗口）
- [ ] 定期更新依赖（`pom.xml` + `package.json`）

## 八、应急处理

### 8.1 服务宕机

```bash
# 1. 检查服务状态
systemctl status nginx mysql redis  # 或 docker ps

# 2. 查看最近错误日志
tail -50 logs/error.log

# 3. 重启服务
# 按依赖顺序：MySQL → Redis → 后端 → Nginx

# 4. 验证恢复
curl http://localhost:8080/actuator/health
```

### 8.2 数据异常

```bash
# 检查最近被修改的数据
SELECT * FROM t_product WHERE updated_at > DATE_SUB(NOW(), INTERVAL 1 HOUR);

# 检查操作日志
SELECT * FROM t_operation_log 
WHERE created_at > DATE_SUB(NOW(), INTERVAL 1 HOUR)
ORDER BY created_at DESC LIMIT 20;
```

### 8.3 紧急回滚

```bash
# 1. 停止后端
kill $(cat app.pid)

# 2. 恢复数据库
mysql -u root -p industrial_gas_alarm_corp < backup/latest.sql

# 3. 重启后端
java -jar app.jar &

# 4. 验证
curl http://localhost:8080/actuator/health
```
