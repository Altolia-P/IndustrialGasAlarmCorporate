# 功能测试计划

> 项目 V1.6 全功能验收测试，覆盖 18 个后端域（15 领域 + 3 微服务模块）+ 5 个前端入口（含数据大屏）。

## 测试环境准备

### 1. 启动依赖服务

```bash
# MySQL 8.0 — 确保运行在 localhost:3306
# 初始化数据库：执行 Gas-ToB-SQL.sql

# Redis — 确保运行在 localhost:6379
```

### 2. 启动后端

```bash
cd Code/backend/IndustrialGasAlarmCorporate
mvnw spring-boot:run
# 启动后确认: http://localhost:8080
```

### 3. 启动前端

```bash
cd Code/frontend
npm install    # 首次运行
npm run dev
# 启动后确认: http://localhost:5173
```

### 4. 测试账号准备

后端启动后先注册一个管理员账号：

```
POST /api/v1/admin/register
{
  "username": "admin_test",
  "password": "Test@123456"
}
```

## 第四轮：设备报警引擎（核心集成测试）

### 4.1 模拟设备数据上报

```bash
# 确认至少有一个 NORMAL 状态的设备 + 一条启用的 THRESHOLD 规则
# 使用 device-simulator 模块或直接 curl

curl -X POST http://localhost:8080/api/v1/public/device-data \
  -H "Content-Type: application/json" \
  -d '{
    "deviceUuid": "<设备UUID>",
    "gasType": "CH4",
    "concentration": 0.05,
    "temperature": 25.0,
    "humidity": 60.0,
    "battery": 3.7,
    "timestamp": "2026-05-27 10:00:00"
  }'
```

| # | 测试项 | 预期结果 | 通过 |
|---|--------|---------|------|
| 1 | 正常数据上报（低于阈值） | 数据保存到 t_device_data_point，不触发报警 | ☐ |
| 2 | **超阈值数据上报** | 数据保存 + 报警记录创建（状态 PENDING）+ 站内通知创建 | ☐ |
| 3 | **滑动窗口验证** | 窗口内持续超阈值 → 仅首次触发；低于阈值 → 不触发 | ☐ |
| 4 | **5 分钟冷却验证** | 首次报警后 5 分钟内，同设备同规则再次超阈值 → 不重复报警 | ☐ |
| 5 | **冷却过期后重新触发** | 5 分钟后再次超阈值 → 创建新报警 | ☐ |
| 6 | 自动创建工单 | 规则开启 autoCreateWorkOrder → 报警创建时自动生成工单 | ☐ |
| 7 | 设备详情页数据点展示 | 上报的数据点出现在该设备的详情页 | ☐ |

### 4.2 报警状态流转全链路

```
报警触发 → PENDING → 管理员确认(CONFIRMED) → 解决(RESOLVED) → 关闭(CLOSED)
```

| # | 测试项 | 预期结果 | 通过 |
|---|--------|---------|------|
| 1 | 完整流转 PENDING→CONFIRMED→RESOLVED→CLOSED | 每步状态正确，通知记录可见 | ☐ |
| 2 | 跳过状态（PENDING 直接 resolve） | 系统允许或给出错误提示 | ☐ |
