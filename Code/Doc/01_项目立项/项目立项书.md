# 工业气体报警企业官网系统 — 项目立项书

## 一、项目背景

### 1.1 行业背景

工业气体检测是石油化工、冶金钢铁、能源电力、市政管廊等行业的**安全刚需**。国家强制性标准 GB 50493《石油化工可燃气体和有毒气体检测报警设计标准》要求化工园区危险气体在线监测覆盖率 100%。

当前市场上气体检测设备厂商普遍存在"重硬件、轻软件"的问题——设备本身性能达标，但配套的企业官网、远程监控平台、客户服务系统严重滞后。大多数厂商官网停留在 2010 年代水平，缺少产品在线展示、解决方案内容营销、客户自助服务等现代 B2B 官网必备功能。

### 1.2 项目缘起

本项目定位为 **InterSense（英森思）品牌的企业官网系统**——一家虚构但高度仿真的工业气体检测设备制造商。项目覆盖从市场推广（产品展示、解决方案、新闻动态）、客户转化（在线留言、资料下载）、到售后运维（设备管理、告警监控、工单跟踪）的完整业务链路。

### 1.3 与课程关系

本项目作为软件工程 NIIT 专业的毕业设计项目，目标是展示以下能力：

- **系统设计能力**：DDD 领域驱动设计、分层架构、RESTful API 设计
- **全栈开发能力**：Spring Boot 3 + Vue 3 前后端分离
- **工程化能力**：Git 版本管理、数据库版本迁移、文档体系
- **安全意识**：JWT 认证、BCrypt 密码加密、登录锁定、RBAC 权限

## 二、项目目标

### 2.1 业务目标

| 目标 | 描述 | 衡量标准 |
|------|------|---------|
| 品牌展示 | 构建专业的 B2B 企业官网，展示产品线和行业解决方案 | 9 大产品 + 4 大解决方案 + 4 篇新闻 |
| 客户转化 | 通过在线留言和资料下载收集销售线索 | 完整的留言→员工指派→跟进流程 |
| 设备运维 | 提供设备远程管理和告警监控能力 | 设备注册→数据采集→告警规则→通知→工单闭环 |
| 内容营销 | 支持解决方案文章和行业新闻发布 | CMS 内容管理（分类+富文本+封面图） |

### 2.2 技术目标

| 目标 | 描述 |
|------|------|
| DDD 四层架构 | interfaces / application / domain / infrastructure 严格分层 |
| 前后端分离 | Vue 3 SPA + Spring Boot REST API，通过 Axios + JWT 通信 |
| 安全体系 | JWT 双 Token（access 30min + refresh 7d）+ BCrypt + 登录锁定（Redis）+ 黑名单 |
| 事件驱动 | EventOutbox 模式实现告警→通知→工单的可靠异步流转 |
| SQL 安全 | MyBatis-Plus 参数化查询，全项目零 SQL 注入风险 |
| 分布式基础 | Redisson 分布式锁 + Nacos 配置中心 + Spring Cloud 微服务预留 |

## 三、项目范围

### 3.1 功能模块

```
┌──────────────────────────────────────────────────────┐
│                    前台门户 (/)                        │
│  首页 │ 产品中心 │ 解决方案 │ 新闻动态 │ 关于我们       │
│  资料下载 │ 在线留言 │ AI 助手                         │
├──────────────────────────────────────────────────────┤
│                    客户中心 (/user)                    │
│  个人中心 │ 我的设备 │ 设备数据 │ 告警记录 │ 我的工单   │
├──────────────────────────────────────────────────────┤
│                    后台管理 (/admin)                   │
│  仪表盘 │ 产品管理 │ 内容管理 │ 分类管理 │ 留言管理     │
│  工单管理 │ 用户管理 │ 员工管理 │ 设备管理 │ 告警规则   │
│  告警记录 │ 通知管理 │ 客户360 │ 系统配置 │ 文件下载   │
│  操作日志 │ AI 客服                                   │
├──────────────────────────────────────────────────────┤
│                    员工后台 (/staff)                   │
│  工作台 │ 工单处理 │ 留言处理 │ 通知 │ 个人信息        │
├──────────────────────────────────────────────────────┤
│                    数据大屏 (/dashboard)               │
│  实时设备状态 │ 告警统计 │ 趋势图（WebSocket 推送）     │
└──────────────────────────────────────────────────────┘
```

### 3.2 核心数据实体（18 张表）

| 领域 | 表名 | 说明 |
|------|------|------|
| 用户 | t_admin_user | 管理员/员工/客户统一用户表 |
| 员工 | t_staff | 员工档案（关联登录账号） |
| 产品 | t_product / t_product_image / t_product_attribute | 产品主表+图片+属性 |
| 分类 | t_category | 产品分类+内容分类 |
| 内容 | t_content | 解决方案+新闻（富文本） |
| 留言 | t_contact_message | 客户在线留言（三态流转） |
| 工单 | t_work_order | 技术支持/售后/告警工单 |
| 评论 | t_comment | 多态评论（产品/内容/工单） |
| 设备 | t_device | 设备注册管理（四态状态机） |
| 数据点 | t_device_data_point | 时序监测数据（device-collector 库） |
| 告警 | t_alert_rule / t_alert | 告警规则+告警记录（四态流转） |
| 通知 | t_notification | 站内通知 + SMS/Email 通道 |
| 文件 | t_download_file | 资料下载（公开/私有） |
| 基础设施 | t_system_config / t_operation_log / t_event_outbox | 配置/审计/可靠事件 |

### 3.3 不包含的范围

- 实际硬件设备对接（使用模拟数据）
- 真实短信/邮件发送（留有接口，演示用 Mock）
- 支付/合同管理（B2B 官网阶段不需要）
- 移动端 APP（仅 Web 端）

## 六、风险与应对

| 风险 | 等级 | 应对措施 |
|------|------|---------|
| 前端开发经验不足 | 中 | 使用 Element Plus 组件库降低 UI 开发门槛 |
| 安全漏洞 | 高 | Spring Security + JWT + BCrypt + SQL 参数化 + QA 代码审查 |
| 数据库设计返工 | 中 | 先 ER 图后编码，版本化迁移脚本 |
| AI 辅助质量不可控 | 中 | QA Agent 双重审查，关键逻辑人工复审 |
| 单人开发效率瓶颈 | 低 | AI Agent 集群自动化任务拆解与代码审查 |
