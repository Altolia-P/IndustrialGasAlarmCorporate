| 注释 | 类 Javadoc + 关键方法注释 + 复杂算法行内注释（中文） |

## 五、关键实现细节

### 5.1 JWT 双 Token 机制

```java
// 登录成功 → 返回两个 Token
accessToken  = JWT(uid, role, exp=30min)   // 短期，调用 API
refreshToken = JWT(uid, exp=7d)            // 长期，仅用于刷新

// Token 刷新流程
POST /api/auth/refresh { refreshToken }
→ 验证 refreshToken 不在黑名单
→ 生成新的 accessToken + refreshToken
→ 旧 refreshToken 加入黑名单（防止重用）
```

### 5.2 登录锁定（Redis）

```java
// Redis Key: login:fail:{username}
// 失败 → INCR → 达5次 → EXPIRE 1800 (30分钟) → 返回 423
// 成功 → DEL key
// 每次 login 先 GET key → 存在且 ≥ 5 → 直接拒绝
```

### 5.3 告警引擎（AlertEngine）

```
定时任务 (每 30s)
    ↓
查询所有 enabled=1 的告警规则
    ↓
对每条规则：
  ├── THRESHOLD → 查询设备最近 durationSeconds 内的数据点
  │               所有浓度 > threshold → 创建 Alert(CRITICAL)
  ├── OFFLINE → 查询设备最后数据点时间
  │             > durationSeconds → 创建 Alert(WARNING)
  └── LOW_BATTERY → 查询最后数据点 battery < 阈值
                    → 创建 Alert(INFO)
    ↓
Alert 创建 → EventOutbox 写入事件
    ↓
NotificationService 消费事件 → 发送 SMS/EMAIL
    ↓
auto_create_work_order=1 且 CRITICAL → 自动创建工单
```

### 5.4 EventOutbox 可靠事件投递

```
┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│ Service 层    │────▶│ t_event_     │────▶│ Listener     │
│ 写业务 + 写事件│     │ outbox       │     │ 消费事件     │
│ (同一事务)     │     │ (PENDING)    │     │ → SENT       │
└──────────────┘     └──────────────┘     └──────────────┘
                            │
                    定时任务扫描 PENDING
                    → 重试 FAILED 事件
```

### 5.5 设备 API Token 认证

```java
// 设备端请求头: X-API-Token: {apiToken}
// ApiTokenFilter:
//   1. 提取 token → SHA256(token)  → 查 t_device.api_token
//   2. 匹配成功 → 设置 deviceUuid 到 SecurityContext
//   3. 匹配失败 → 401

// 设备注册时生成 token:
//   apiToken = SHA256(serialNumber + secret_salt)
//   写入 t_device.api_token，交付给设备端烧录
```
