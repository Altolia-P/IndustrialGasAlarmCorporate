## 二、开发模式

### 2.1 AI 辅助开发流程

本项目采用 Hermes 多智能体集群辅助开发，架构如下：

```
用户（岳阳）
   │
   ▼
秘书（L1 协调层）  ←── 接收任务 → 拆解 → 派发 → 汇总汇报
   │
   ├──▶ 架构师（技术选型）
   │
   ├──▶ leader-backend（L2）──▶ worker-java-1/2（L3 编码）
   │         └──▶ QA（代码审查）  └──▶ DBA（SQL 审查）
   │
   └──▶ leader-frontend（L2）──▶ worker-vue-1/2（L3 编码）
             └──▶ QA（代码审查）
```

**工作流：**
1. 用户描述需求 → 秘书 clarify 确认 → board-a 创建任务
2. leader-backend/frontend 拆解为 board-b 原子任务
3. L3 技术员认领 → 编码提交 → QA 审查 PASS/FAIL
4. L2 组长汇总 → 秘书推送给用户

### 2.2 版本管理策略

```
main          ─── ● ──────── ● ──────── ● ── 稳定发布版
                    \         / \         /
develop       ─── ● ─ ● ─ ● ─ ● ─ ● ─ ● ── 开发主线
                    \   /
feature-auth   ─── ● ─ ●                    功能分支
```

- **分支命名**：`feature/<模块名>` → `develop` → `main`
- **提交粒度**：每个功能点独立提交，message 格式 `feat: / fix: / docs: / refactor:`
- **代码审查**：QA Agent 自动审查 board-b 每个子任务
