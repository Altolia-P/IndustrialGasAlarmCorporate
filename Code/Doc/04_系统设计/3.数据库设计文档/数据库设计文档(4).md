## 一、E-R 概览（保持不变）

- 分类表 t_category 与产品、内容为逻辑引用关系，不使用物理外键
- 产品 t_product 下挂产品图片 t_product_image、产品属性 t_product_attribute
- 内容 t_content 用于解决方案/新闻动态
- 留言 t_contact_message 记录客户线索及处理信息
- 管理员 t_admin_user 支持 BCrypt 哈希、登录失败锁定和 role 字段

## 二、表结构详细设计

### 1. 分类表 (t_category)

```sql
CREATE TABLE t_category (
    category_uuid CHAR(36) PRIMARY KEY COMMENT '分类唯一标识',
    name          VARCHAR(200) NOT NULL COMMENT '分类名称',
    type          VARCHAR(20)  NOT NULL COMMENT '分类类型：PRODUCT_CATEGORY / CONTENT_CATEGORY',
    parent_uuid   CHAR(36)     NULL COMMENT '父分类ID',
    sort_order    INT          NOT NULL DEFAULT 0 COMMENT '排序序号',
    deleted       TINYINT(1)   NOT NULL DEFAULT 0 COMMENT '逻辑删除',
    created_at    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    updated_at    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    INDEX idx_category_type (type),
    INDEX idx_parent_uuid (parent_uuid),
    CHECK (type IN ('PRODUCT_CATEGORY','CONTENT_CATEGORY'))
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='分类表';
```

------

### 2. 产品表 (t_product)

**原因**：

- 架构设计文档明确要求全局唯一
- 避免前后端校验逻辑不一致

**修正示例**：

```sql
CREATE TABLE t_product (
    product_uuid  CHAR(36)  PRIMARY KEY COMMENT '产品唯一标识',
    name          VARCHAR(200) NOT NULL COMMENT '产品名称',
    description   TEXT         NULL COMMENT '产品描述',
    status        VARCHAR(20)  NOT NULL DEFAULT 'DRAFT' COMMENT 'DRAFT / PUBLISHED / UNPUBLISHED',
    cover_image   VARCHAR(500) NULL COMMENT '封面图片URL',
    category_uuid CHAR(36)  NOT NULL COMMENT '所属分类ID',
    deleted       TINYINT(1) NOT NULL DEFAULT 0 COMMENT '逻辑删除',
    created_at    DATETIME  NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    updated_at    DATETIME  NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    CONSTRAINT uk_name UNIQUE (name),
    INDEX idx_product_category_status (category_uuid, status),
    CHECK (status IN ('DRAFT','PUBLISHED','UNPUBLISHED'))
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='产品表';
```

### 6. 留言表 (t_contact_message)

**原因**：

- 架构文档建议 `ORDER BY submitted_at DESC` 使用索引
- 避免后台列表查询 filesort

**修正示例**：

```sql
CREATE TABLE t_contact_message (
    message_uuid CHAR(36)  PRIMARY KEY COMMENT '留言唯一标识',
    name         VARCHAR(100) NOT NULL COMMENT '联系人姓名',
    phone        VARCHAR(20)  NOT NULL COMMENT '联系电话',
    content      TEXT         NOT NULL COMMENT '需求描述',
    ip           VARCHAR(45)  NOT NULL COMMENT '提交IP',
    status       VARCHAR(20)  NOT NULL DEFAULT 'PENDING' COMMENT 'PENDING / PROCESSED',
    processor    VARCHAR(100) NULL COMMENT '处理人',
    remark       VARCHAR(500) NULL COMMENT '处理备注',
    submitted_at DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '提交时间',
    processed_at DATETIME     NULL COMMENT '处理时间',
    deleted      TINYINT(1)   NOT NULL DEFAULT 0 COMMENT '逻辑删除',
    created_at   DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '记录创建时间',
    updated_at   DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    INDEX idx_msg_status_submitted (status, submitted_at DESC),
    INDEX idx_msg_phone_submitted (phone, submitted_at),
    INDEX idx_msg_ip_submitted (ip, submitted_at),
    CHECK (status IN ('PENDING','PROCESSED'))
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='客户留言表';
```

### 7. 管理员用户表 (t_admin_user)

**原因**：

- 类图中 `User` 聚合根用 `locked` 停用账号，没有逻辑删除概念
- 业务上管理员无需逻辑删除，避免增加查询/认证复杂度

**修正示例**：

```sql
CREATE TABLE t_admin_user (
    user_uuid     CHAR(36)  PRIMARY KEY COMMENT '用户唯一标识',
    username      VARCHAR(50)  NOT NULL COMMENT '登录用户名',
    password_hash VARCHAR(255) NOT NULL COMMENT 'BCrypt密码哈希',
    fail_count    INT          NOT NULL DEFAULT 0 COMMENT '连续失败次数',
    locked        TINYINT(1)   NOT NULL DEFAULT 0 COMMENT '是否锁定',
    lock_time     DATETIME     NULL COMMENT '锁定时间',
    last_login_at DATETIME     NULL COMMENT '最后登录时间',
    role          VARCHAR(20)  NOT NULL DEFAULT 'ADMIN' COMMENT '角色',
    created_at    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    updated_at    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    CONSTRAINT uk_username UNIQUE (username)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='管理员用户表';
```

## 三、设计决策说明

| 决策点               | 说明                                                         |
| -------------------- | ------------------------------------------------------------ |
| 主键 UUID            | CHAR(36)，由应用层生成，隐藏业务信息，减少索引开销           |
| 逻辑删除字段 deleted | 所有表统一加 deleted 支持逻辑删除，索引查询需加 WHERE deleted=0 |
| 枚举字段约束         | status/type 使用 CHECK 限制有效值，避免非法值                |
| 无物理外键           | 表间关系由应用层保证，保证性能和易维护                       |
| 审计字段自动填充     | created_at / updated_at 由 MyBatis-Plus 自动填充             |
| 联合唯一约束         | Product: name + category_uuid，防止不同分类重名              |
| 留言防刷索引         | 组合索引 (phone, submitted_at) 和 (ip, submitted_at) 支持高效查询 |
| 值对象独立子表       | ProductImage / ProductAttribute 作为独立表，便于查询和管理   |
