# 数据库设计文档 V1.5

## 文档信息

- **项目名称**：工业气体报警企业官网系统
- **设计依据**：《类图设计文档（最终版）》《架构设计文档 V1.6》《API 接口文档 V1.2》
- **数据库**：MySQL 8.0
- **字符集**：utf8mb4
- **存储引擎**：InnoDB
- **主键策略**：全表 UUID v4 CHAR(36)（应用层生成）
- **乐观锁**：所有业务表含 `version INT NOT NULL DEFAULT 0`，MyBatis-Plus `@Version` 维护（t_staff 除外，当前未配置乐观锁）
- **逻辑删除**：`deleted TINYINT(1) NOT NULL DEFAULT 0`（t_admin_user 除外）
- **审计字段**：`created_at` / `updated_at` 由 MyBatis-Plus MetaObjectHandler 自动填充

## 二、表结构详细设计

### 1. 分类表 (t_category)

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| category_uuid | CHAR(36) | PRIMARY KEY | 分类唯一标识 |
| name | VARCHAR(200) | NOT NULL | 分类名称 |
| type | VARCHAR(20) | NOT NULL | PRODUCT_CATEGORY / CONTENT_CATEGORY |
| parent_uuid | CHAR(36) | NULL | 父分类ID，支持树形结构 |
| sort_order | INT | NOT NULL DEFAULT 0 | 排序序号 |
| version | INT | NOT NULL DEFAULT 0 | 乐观锁版本号 |
| deleted | TINYINT(1) | NOT NULL DEFAULT 0 | 逻辑删除 |
| created_at | DATETIME | NOT NULL DEFAULT CURRENT_TIMESTAMP | 创建时间 |
| updated_at | DATETIME | NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP | 更新时间 |

**索引**：`idx_category_type`(type), `idx_parent_uuid`(parent_uuid)

```sql
CREATE TABLE t_category (
    category_uuid CHAR(36) PRIMARY KEY COMMENT '分类唯一标识',
    name          VARCHAR(200) NOT NULL COMMENT '分类名称',
    type          VARCHAR(20)  NOT NULL COMMENT '分类类型：PRODUCT_CATEGORY / CONTENT_CATEGORY',
    parent_uuid   CHAR(36)     NULL COMMENT '父分类ID',
    sort_order    INT          NOT NULL DEFAULT 0 COMMENT '排序序号',
    version       INT          NOT NULL DEFAULT 0 COMMENT '乐观锁版本号',
    deleted       TINYINT(1)   NOT NULL DEFAULT 0 COMMENT '逻辑删除',
    created_at    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    updated_at    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    INDEX idx_category_type (type),
    INDEX idx_parent_uuid (parent_uuid),
    CHECK (type IN ('PRODUCT_CATEGORY','CONTENT_CATEGORY'))
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='分类表';
```

### 6. 留言表 (t_contact_message) — V1.3 变更

**V1.3 变更说明**：
- `status` 增加 `IN_PROGRESS`，支持三态流转：`PENDING → IN_PROGRESS → PROCESSED`
- `processor` 字段移除，替换为 `assigned_staff_uuid` + `assigned_staff_name`，支持指派到具体员工
- 对应前端 API：`POST /public/messages`（提交）、`PUT /admin/messages/{uuid}/assign`（指派）、`PUT /admin/messages/{uuid}/complete`（完成）

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| message_uuid | CHAR(36) | PRIMARY KEY | 留言唯一标识 |
| name | VARCHAR(100) | NOT NULL | 联系人姓名 |
| phone | VARCHAR(20) | NOT NULL | 联系电话 |
| content | TEXT | NOT NULL | 需求描述 |
| ip | VARCHAR(45) | NOT NULL | 提交IP（后端获取，兼容IPv6） |
| status | VARCHAR(20) | NOT NULL DEFAULT 'PENDING' | PENDING / IN_PROGRESS / PROCESSED |
| assigned_staff_uuid | CHAR(36) | NULL | 指派员工UUID |
| assigned_staff_name | VARCHAR(100) | NULL | 指派员工姓名（冗余，避免JOIN） |
| remark | VARCHAR(500) | NULL | 处理备注 |
| version | INT | NOT NULL DEFAULT 0 | 乐观锁版本号 |
| submitted_at | DATETIME | NOT NULL DEFAULT CURRENT_TIMESTAMP | 提交时间 |
| processed_at | DATETIME | NULL | 处理完成时间 |
| deleted | TINYINT(1) | NOT NULL DEFAULT 0 | 逻辑删除 |
| created_at | DATETIME | NOT NULL DEFAULT CURRENT_TIMESTAMP | 记录创建时间 |
| updated_at | DATETIME | NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP | 更新时间 |

**索引**：`idx_msg_status_submitted`(status, deleted, submitted_at DESC), `idx_msg_phone_submitted`(phone, submitted_at), `idx_msg_ip_submitted`(ip, submitted_at), `idx_msg_assigned_staff`(assigned_staff_uuid)

```sql
CREATE TABLE t_contact_message (
    message_uuid        CHAR(36)     PRIMARY KEY COMMENT '留言唯一标识',
    name                VARCHAR(100) NOT NULL COMMENT '联系人姓名',
    phone               VARCHAR(20)  NOT NULL COMMENT '联系电话',
    content             TEXT         NOT NULL COMMENT '需求描述',
    ip                  VARCHAR(45)  NOT NULL COMMENT '提交IP',
    status              VARCHAR(20)  NOT NULL DEFAULT 'PENDING' COMMENT 'PENDING / IN_PROGRESS / PROCESSED',
    assigned_staff_uuid CHAR(36)     NULL COMMENT '指派员工UUID',
    assigned_staff_name VARCHAR(100) NULL COMMENT '指派员工姓名（冗余）',
    remark              VARCHAR(500) NULL COMMENT '处理备注',
    version             INT          NOT NULL DEFAULT 0 COMMENT '乐观锁版本号',
    submitted_at        DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '提交时间',
    processed_at        DATETIME     NULL COMMENT '处理完成时间',
    deleted             TINYINT(1)   NOT NULL DEFAULT 0 COMMENT '逻辑删除',
    created_at          DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '记录创建时间',
    updated_at          DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    INDEX idx_msg_status_submitted (status, deleted, submitted_at DESC),
    INDEX idx_msg_phone_submitted (phone, submitted_at),
    INDEX idx_msg_ip_submitted (ip, submitted_at),
    INDEX idx_msg_assigned_staff (assigned_staff_uuid),
    CHECK (status IN ('PENDING','IN_PROGRESS','PROCESSED'))
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='客户留言表';
```

### 7. 用户表 (t_admin_user) — V1.3 变更

**V1.3 变更说明**：
- 新增 `phone` 字段，支持客户注册时填写手机号
- 新增 `company` 字段，支持客户注册时填写公司名称
- `role` 默认值改为 `USER`，支持三种角色：`ADMIN`（管理员）、`STAFF`（员工）、`USER`（注册客户）
- 客户通过 `POST /public/register` 注册，默认 role=USER

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| user_uuid | CHAR(36) | PRIMARY KEY | 用户唯一标识 |
| username | VARCHAR(50) | NOT NULL UNIQUE | 登录用户名 |
| password_hash | VARCHAR(255) | NOT NULL | BCrypt 密码哈希 |
| phone | VARCHAR(20) | NULL | 手机号 |
| company | VARCHAR(200) | NULL | 公司名称 |
| fail_count | INT | NOT NULL DEFAULT 0 | 连续登录失败次数 |
| locked | TINYINT(1) | NOT NULL DEFAULT 0 | 是否锁定（0/1） |
| lock_time | DATETIME | NULL | 锁定时间 |
| last_login_at | DATETIME | NULL | 最后登录时间 |
| role | VARCHAR(20) | NOT NULL DEFAULT 'USER' | 角色：ADMIN / STAFF / USER |
| version | INT | NOT NULL DEFAULT 0 | 乐观锁版本号 |
| created_at | DATETIME | NOT NULL DEFAULT CURRENT_TIMESTAMP | 创建时间 |
| updated_at | DATETIME | NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP | 更新时间 |

**索引**：`uk_username` UNIQUE(username)

```sql
CREATE TABLE t_admin_user (
    user_uuid     CHAR(36)     PRIMARY KEY COMMENT '用户唯一标识',
    username      VARCHAR(50)  NOT NULL COMMENT '登录用户名',
    password_hash VARCHAR(255) NOT NULL COMMENT 'BCrypt密码哈希',
    phone         VARCHAR(20)  NULL COMMENT '手机号',
    company       VARCHAR(200) NULL COMMENT '公司名称',
    fail_count    INT          NOT NULL DEFAULT 0 COMMENT '连续失败次数',
    locked        TINYINT(1)   NOT NULL DEFAULT 0 COMMENT '是否锁定',
    lock_time     DATETIME     NULL COMMENT '锁定时间',
    last_login_at DATETIME     NULL COMMENT '最后登录时间',
    role          VARCHAR(20)  NOT NULL DEFAULT 'USER' COMMENT '角色：ADMIN / STAFF / USER',
    version       INT          NOT NULL DEFAULT 0 COMMENT '乐观锁版本号',
    created_at    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    updated_at    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    CONSTRAINT uk_username UNIQUE (username)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户表';
```

## 三、设计决策说明

| 决策点 | 说明 |
|--------|------|
| 全表 UUID 主键 | CHAR(36)，应用层生成，分库分表无冲突，微服务独立部署安全 |
| 乐观锁 version | 所有业务表含 version 列，MyBatis-Plus `@Version` 自动维护 |
| 逻辑删除 deleted | 除 t_admin_user 外所有业务表统一加 deleted |
| 枚举字段 CHECK | status/type 使用 CHECK 约束限制有效值，应用层 `@Valid` 双重校验 |
| 无物理外键 | 表间关系由应用层保证，微服务独立部署不依赖 DB 级约束 |
| 审计字段自动填充 | created_at / updated_at 由 MyBatis-Plus MetaObjectHandler 自动填充 |
| 员工表独立 | t_staff 独立于 t_admin_user，员工信息和登录账号解耦，支持灵活的人员变动 |
| 消息三态流转 | PENDING → IN_PROGRESS → PROCESSED，assign 触发 IN_PROGRESS，markProcessed 触发 PROCESSED |
| 工单三态流转 | PENDING → IN_PROGRESS → COMPLETED，assign/complete 操作触发状态变更（Controller 待开发） |
| 用户注册 | 通过 POST /public/register 注册，默认 role=USER，不绑定员工信息 |
| 冗余员工姓名 | t_contact_message / t_work_order 冗余 assigned_staff_name，避免列表查询 JOIN |
| 留言防刷索引 | 组合索引 (phone, submitted_at) 和 (ip, submitted_at) 支持高效防刷查询 |
| 设备监控平台 5 表 | t_device（设备）、t_device_data_point（时序数据）、t_alert_rule（报警规则）、t_alert（报警记录）、t_notification（通知记录） |
| 报警引擎 Redis | ZSet 滑动窗口（device:window:{uuid}）+ SETNX 去重抑制（alert:suppress:{uuid}:{rule}）+ JSON 缓存（dashboard:stats） |
| 设备状态机 | NORMAL ⇄ ABNORMAL、NORMAL→OFFLINE、任意→MAINTENANCE→NORMAL |
| 报警四态流转 | PENDING→CONFIRMED→RESOLVED→CLOSED（支持从任意非关闭状态直接关闭） |

## 五、MyBatis-Plus 自动填充配置参考

```java
@Component
public class MyMetaObjectHandler implements MetaObjectHandler {
    @Override
    public void insertFill(MetaObject metaObject) {
        this.strictInsertFill(metaObject, "createdAt", Date::new, Date.class);
        this.strictInsertFill(metaObject, "updatedAt", Date::new, Date.class);
    }

    @Override
    public void updateFill(MetaObject metaObject) {
        this.strictUpdateFill(metaObject, "updatedAt", Date::new, Date.class);
    }
}
```

在 PO 类对应字段添加注解：
```java
@TableField(fill = FieldFill.INSERT)
private Date createdAt;

@TableField(fill = FieldFill.INSERT_UPDATE)
private Date updatedAt;
```

此配置配合 DDL 中的 `DEFAULT CURRENT_TIMESTAMP` 及 `ON UPDATE CURRENT_TIMESTAMP`，提供数据库层面兜底。
