### 3.2 事件发布时机说明

| 聚合根           | 事件                    | 发布方式                                      | 触发时机                                               | 发布方                                                       |
| ---------------- | ----------------------- | --------------------------------------------- | ------------------------------------------------------ | ------------------------------------------------------------ |
| `Product`        | `ProductPublishedEvent` | `DomainEvent.collectEvent()` + 聚合根内部收集 | `publish()` 方法执行后                                 | 聚合根内部记录事件，Service 层调用 `EventBus.publish()` 统一发布 |
| `ContactMessage` | `MessageSubmittedEvent` | 同上                                          | `submit()` 方法执行后                                  | 同上                                                         |
| `User`           | `AccountLockedEvent`    | 同上                                          | `incrementFailCount()` 中，`isLocked()` 变为 `true` 时 | 同上                                                         |

**事件收集机制**（聚合根基类可选设计）：
```java
abstract class AggregateRoot {
    private List<DomainEvent> events = new ArrayList<>();

    protected void collectEvent(DomainEvent event) {
        this.events.add(event);
    }

    public List<DomainEvent> getEvents() {
        return Collections.unmodifiableList(events);
    }

    public void clearEvents() {
        this.events.clear();
    }
}
```
Service 层在调用聚合根方法后：
1. 获取聚合根 `events`
2. 通过 `EventBus.publish()` 逐条发布
3. 调用 `clearEvents()`
4. 以上操作在事务边界内完成

## 十、事务边界与事件发布

### 10.1 事务边界定义

| 服务方法                              | 事务             | 事件发布                                                     |
| ------------------------------------- | ---------------- | ------------------------------------------------------------ |
| `ProductServiceImpl.publishProduct()` | `@Transactional` | 状态保存 → 获取聚合根事件 → `EventBus.publish()` → 事务提交后事件生效 |
| `MessageServiceImpl.submitMessage()`  | `@Transactional` | 同上                                                         |
| `AuthServiceImpl.login()`             | `@Transactional` | 登录成功/失败计量 → 若锁定则发布 `AccountLockedEvent`        |

### 10.2 事务与事件一致性策略

- **采用“事务内收集 + 后提交事件”模式**
  1. 在事务中调用聚合根领域方法
  2. 聚合根内部通过 `collectEvent()` 收集事件
  3. Repository `save()` 后，Service 获取事件列表
  4. 事务提交后，通过 `EventBus.publish()` 逐一发布
- **绝不**在事务未提交时异步发送事件
- 若业务需要“发件箱模式”，另行实现（基础设施层提供 `EventStore`）

## 十二、基础设施层说明

### 12.1 Repository 实现

- **持久化框架**：**MyBatis-Plus**（团队统一标准）
- **实体映射**：
  - **PO（持久化对象）**：如 `ProductPO`、`ContentPO`、`CategoryPO`、`MessagePO`、`UserPO`，放在 `infrastructure.repository.po` 包，使用 `@TableName` 注解对应数据库表。
  - **Mapper 接口**：继承 MyBatis-Plus 的 `BaseMapper<PO>`，提供基础 CRUD 能力，放在 `infrastructure.repository.mapper` 包。
  - **Repository 实现**：在 `infrastructure.repository.impl` 中注入对应 `Mapper`，负责 **PO ↔ 领域对象转换**，并实现 `domain.repository` 中定义的接口。
- **聚合根内部值对象**（`ProductImage`、`ProductAttribute`）存储策略：
  - **方案一（推荐）**：独立子表 `t_product_image`、`t_product_attribute`，通过 `product_uuid` 关联。
  - **方案二**：JSON 列存储，MyBatis-Plus 提供 `@TableField(typeHandler = JacksonTypeHandler.class)` 支持。
- **领域层无侵入**：`domain` 包中的聚合根、Repository 接口不依赖任何 MyBatis-Plus 注解或类。

### 12.2 缓存实现

- **缓存技术**：**Redis**
- **核心使用场景**：
  - **分类列表缓存**：`getCategoriesByType` 查询结果缓存 1 小时，通过 Spring Cache + Redis 实现（`@Cacheable`）。
  - **表单防刷**：
    - 同一手机号 60 秒内重复提交限制，使用 Redis `SET key value EX 60 NX` 原子操作。
    - 同一 IP 每分钟最多 3 次，使用 `INCR` + `EXPIRE` 滑动窗口。
  - **JWT 黑名单**（可选）：登出或修改密码时，将旧 token 加入 Redis Set，过期时间与 token 剩余有效期一致。
  - **分布式锁**（预留）：批量操作或定时任务可用 `Redisson` 或 Redis `SETNX` 实现轻量锁。
- **Redisson 客户端**：推荐使用 Redisson 作为 Redis 客户端，提供分布式锁等高级功能。

### 12.3 审计字段自动维护

`BaseEntity` 包含 `createdAt` 和 `updatedAt` 字段，使用 MyBatis-Plus 的 **自动填充功能** 完成赋值，无需业务代码干预。

实现方式：

- 创建 `MetaObjectHandler` 实现类，在 `insertFill` 和 `updateFill` 方法中自动设置时间字段。
- 在 PO 的 `createdAt` 字段上添加 `@TableField(fill = FieldFill.INSERT)`，`updatedAt` 字段上添加 `@TableField(fill = FieldFill.INSERT_UPDATE)`。

### 12.4 分页实现

MyBatis-Plus 提供 `PaginationInnerInterceptor` 分页插件，在 `MybatisPlusConfig` 中注册即可。Service 层调用 MyBatis-Plus 的 `Page<T>` 对象传入 `IPage`，Repository 实现中映射为领域层的 `Page` 返回。

### 12.5 EventBus 实现

- **同步/本地**：Spring ApplicationEvent + `@EventListener`
- **异步/消息队列**（可选）：RabbitMQ / Kafka + Spring Cloud Stream

### 12.6 安全实现

- 密码加密：BCrypt（`passwordHash` 由 BCrypt 编码输出）
- 认证：JWT Token（登录成功后生成，包含 `userUuid`、`role` 等）
- JWT 黑名单：基于 Redis Set 实现

## 十四、分层结构与职责

text

```
Controller 层  (PublicController / AdminController)
      ↓ 依赖 Service 接口
Service 层     (接口 + Impl)
      ↓ 依赖 Assembler、Repository、领域对象
Assembler 层   (DTO ↔ Domain 转换)
      ↓
Domain 层      (聚合根、值对象、领域事件、Repository 接口)
      ↑ 实现
Infrastructure 层 (MyBatis-Plus Mapper / Repository 实现, Redis 缓存, EventBus, Security)
```



### 关键规则（重申）

- Controller **只能**依赖 Service 接口，统一返回 `Result<T>`
- Service **编排**流程，调用 Assembler 转换，调用聚合根方法，管理事务；**可调用 Redis 工具类**进行缓存与防刷判断
- Assembler **只做数据映射**，无业务逻辑
- 聚合根 **封装核心业务规则**，内部收集事件
- Repository 接口定义在 Domain 层，实现在 Infrastructure 层，**返回 `Optional`**，内部使用 MyBatis-Plus Mapper 完成持久化
- 跨聚合操作优先通过 `EventBus` 解耦

- **继承**：事件子类继承 `DomainEvent`，所有聚合根可选继承 `BaseEntity`
