## 一、系统概述

### 1.1 设计目标

构建一个 **领域驱动设计 (DDD) 四层架构** 的 B2B 企业官网系统，满足：
- **高内聚低耦合**：业务逻辑集中在 Domain 层，与框架解耦
- **可测试性**：Domain 层零框架依赖，单元测试无需启动 Spring
- **可扩展性**：Assembler 隔离 DTO/Domain/VO，切换 ORM 或前端不影响核心逻辑
- **安全性**：JWT 双 Token + BCrypt + Redis 黑名单 + 登录锁定

### 1.2 技术选型

| 层级 | 技术 | 版本 | 选型理由 |
|------|------|------|---------|
| 语言 | Java | 17 LTS | 长期支持、密封类、Record |
| 框架 | Spring Boot | 3.5.14 | 生态成熟、自动配置 |
| ORM | MyBatis-Plus | 3.5.16 | 零 SQL 基础 CRUD、乐观锁、逻辑删除、分页 |
| 安全 | Spring Security + JJWT | 6.x / 0.12.5 | RBAC + JWT 无状态认证 |
| 数据库 | MySQL | 8.0 | 关系型、utf8mb4、JSON 列 |
| 缓存 | Redis | 7.x | Token 黑名单、登录锁定计数、分布式锁 |
| 分布式 | Redisson + Nacos + RabbitMQ | 3.40.2 / 2.x / 4.x | 分布式锁 + 服务注册 + 设备事件消息队列 |
| 微服务 | Spring Cloud + Spring Cloud Alibaba | 2025.0.0 | device-collector 微服务注册与远程调用 |
| AI | LangChain4j | 1.0.0-beta2 | OpenAI 兼容协议对话 + 嵌入搜索 |
| 前端 | Vue 3 + Element Plus | 3.x / 2.x | 组件化 + 响应式 |

## 二、总体架构

### 2.1 DDD 四层架构

```
┌──────────────────────────────────────────────────────────────┐
│                    interfaces/ (接口层)                       │
│   Controller: 参数校验、路由分发、返回 Result<T>              │
│   权限: @PreAuthorize 注解 + Spring Security                 │
├──────────────────────────────────────────────────────────────┤
│                   application/ (应用层)                       │
│   Service 接口 + ServiceImpl: 业务流程编排                    │
│   @Transactional 事务边界                                    │
│   EventBus.publish() 领域事件发布                            │
├──────────────────────────────────────────────────────────────┤
│                     domain/ (领域层) ★核心                   │
│   聚合根 (AggregateRoot): 零框架注解, 纯 POJO                │
│   Repository 接口: 定义在 domain，实现在 infrastructure       │
│   领域事件 (DomainEvent): 聚合根内部收集                      │
│   值对象 (ValueObject): 不可变                                │
├──────────────────────────────────────────────────────────────┤
│                 infrastructure/ (基础设施层)                  │
│   repository/po/: MyBatis-Plus PO (持久化对象)               │
│   repository/mapper/: BaseMapper<PO> 接口                    │
│   repository/impl/: PO ↔ Domain 转换 + DB 操作               │
│   security/: JWT 过滤器、SecurityConfig                      │
│   config/: MyBatis-Plus、Redis、Nacos 配置                   │
│   event/: EventOutbox 可靠事件投递                           │
├──────────────────────────────────────────────────────────────┤
│                     assembler/ (装配层)                       │
│   DTO ↔ Domain ↔ VO 纯映射，无业务逻辑                        │
└──────────────────────────────────────────────────────────────┘
```

### 2.3 核心设计决策

| 决策 | 方案 | 原因 |
|------|------|------|
| 主键策略 | UUID v4 CHAR(36) | 分布式友好、无自增冲突 |
| 乐观锁 | MyBatis-Plus @Version | 防止并发覆盖 |
| 逻辑删除 | MyBatis-Plus @TableLogic | 数据可恢复 |
| 密码存储 | BCrypt | 行业标准、不可逆 |
| Token 吊销 | Redis Set 黑名单 | JWT 本身无状态，需额外存储 |
| 登录锁定 | Redis String 计数器 | 无状态服务间共享 |
| 事件发布 | EventOutbox 模式 | 可靠投递、不丢事件 |
| API 统一返回 | `Result<T>` (code + message + data) | 前端统一处理 |
| 跨层隔离 | Assembler 层 | Domain 层零 DTO/VO 依赖 |

### 3.3 三命脉闭环

项目核心业务链路——三条命脉形成完整闭环：

```
设备入口              告警联动              通知触达
─────────           ──────────           ─────────
设备注册               数据点入库             告警创建
   │                     │                    │
   ▼                     ▼                    ▼
API Token 认证     AlertEngine 扫描     NotificationService
   │              规则 → 阈值判定        → SMS/EMAIL 发送
   ▼                     │                    │
数据点上报               ▼                    ▼
(t_device_data     创建 Alert          t_notification
 _point 时序追加)  (PENDING)           (SENT/DELIVERED)
                       │
                       ▼
                  auto_create_work_order
                  → 自动生成工单
                  → 指派员工
                  → 告警 CONFIRMED
                  → 处理完成 RESOLVED
```

### 4.3 索引设计原则

- **高频查询列** → 单独索引（如 `device_uuid`、`status`）
- **时序查询** → 联合索引 `(device_uuid, recorded_at DESC)` 用于设备趋势图
- **唯一约束** → `username`、`serial_number`、`(name, category_uuid, deleted)`
- **不建过多索引** → 设备数据点表只有 1 个联合索引（追加写入为主）

## 五、安全架构

### 5.1 认证流程

```
                    ┌─────────────────────┐
                    │   POST /api/auth/   │
                    │      login          │
                    │ username + password │
                    └─────────┬───────────┘
                              │
                    ┌─────────▼───────────┐
                    │  AuthServiceImpl    │
                    │  1. 查 User         │
                    │  2. BCrypt 验证     │
                    │  3. 检查 Redis 锁定 │
                    └─────────┬───────────┘
                              │
              ┌───────────────┼───────────────┐
              ▼               ▼               ▼
        成功             密码错误           已锁定
         │               │                  │
         ▼               ▼                  ▼
  生成双 Token     failCount++       返回 423
  access(30min)    达5次→锁定30min    "账号已锁定"
  refresh(7d)
```

### 5.2 安全层次

| 层次 | 机制 | 实现 |
|------|------|------|
| 传输层 | HTTPS | Nginx 反向代理（生产环境） |
| 认证层 | JWT Bearer Token | Spring Security Filter Chain |
| 授权层 | @PreAuthorize | hasRole('ADMIN') / hasRole('STAFF') |
| 密码层 | BCrypt | 12 rounds |
| 防护层 | 登录锁定 | Redis 计数，5 次/30 分钟 |
| 吊销层 | Token 黑名单 | Redis Set，TTL = token 剩余时间 |
| 数据层 | 参数化查询 | MyBatis-Plus，零 SQL 拼接 |
| 审计层 | 操作日志 | t_operation_log（操作人/IP/目标/详情） |

### 5.3 API 认证矩阵

| 接口前缀 | 认证要求 | 角色 |
|---------|---------|------|
| `/api/v1/public/**` | 无 | GUEST |
| `/api/v1/admin/auth/login` | 无 | GUEST |
| `/api/v1/admin/auth/register` | 无 | GUEST |
| `/api/v1/user/**` | JWT | USER |
| `/api/v1/staff/**` | JWT | STAFF / ADMIN |

## 六、API 设计规范

### 6.1 统一返回格式

```json
{
  "code": 200,
  "message": "success",
  "data": {},
  "success": true
}
```

**业务码约定：**

| code | 含义 |
|------|------|
| 200 | 成功 |
| 400 | 参数校验失败 |
| 401 | 未认证 / Token 过期 |
| 403 | 无权限 |
| 404 | 资源不存在 |
| 423 | 账号已锁定 |
| 500 | 服务器内部错误 |

### 6.2 RESTful 规范

| 操作 | 方法 | URL 示例 |
|------|------|---------|
| 列表 | GET | `/api/admin/products?page=1&size=12&status=PUBLISHED` |
| 详情 | GET | `/api/admin/products/{productUuid}` |
| 新增 | POST | `/api/admin/products` |
| 更新 | PUT | `/api/admin/products/{productUuid}` |
| 删除 | DELETE | `/api/admin/products/{productUuid}` |
| 发布 | PUT | `/api/admin/products/{productUuid}/publish` |

### 6.3 分页规范

```
请求: ?page=1&size=20
响应: {

## 七、部署架构

```
                    ┌──────────────┐
                    │   用户浏览器   │
                    └──────┬───────┘
                           │ HTTPS
                    ┌──────▼───────┐
                    │   Nginx      │
                    │   :80/:443   │
                    │  静态文件 +   │
                    │  反向代理     │
                    └──┬───────┬───┘
                       │       │
              ┌────────▼─┐  ┌─▼────────┐
              │ Vue 3 SPA│  │Spring Boot│
              │  /       │  │ :8080     │
              └──────────┘  └──┬───┬───┘
                               │   │
                     ┌─────────▼┐ ┌▼─────────┐
                     │  MySQL   │ │  Redis   │

- **缓存**：Redis 7.x，独立容器
- **反向代理**：Nginx，SSL 终结 + 静态文件 + API 路由
