### 2.2 核心成就

**三命脉闭环** — 项目最大的技术亮点：

```
设备注册 → API Token 认证 → 数据点上报 (t_device_data_point)
    ↓
AlertEngine 扫描规则 → 阈值/离线/低电量判定 → Alert 创建
    ↓
NotificationService → SMS/EMAIL 发送 → 告警确认
    ↓
CRITICAL 自动生成工单 → 指派员工 → 处理完成 → 闭环
```

这个闭环从 **数据采集 → 智能判定 → 通知触达 → 工单跟踪**，覆盖了工业 IoT 领域的完整业务链路，在毕设级别的项目中属于高完成度的实现。

## 三、技术亮点

### 3.1 DDD 四层架构

| 层 | 亮点 |
|---|------|
| **Domain** | 零框架注解，纯 POJO，单元测试无需启动 Spring |
| **Application** | 15 个 Service 模块，@Transactional 只在 ServiceImpl 层 |
| **Infrastructure** | 17 个 RepositoryImpl + 12 个 Redis Repository + MQ + Feign + WebSocket，PO ↔ Domain 转换隔离 |
| **Assembler** | DTO/Domain/VO 三向纯映射，Controller 层零 Domain 对象 |

### 3.2 安全体系

```
JWT 双 Token (access 30min + refresh 7d)
    +
BCrypt 密码哈希 (12 rounds)
    +
Redis 登录锁定 (5次/30分钟)
    +
Redis Token 黑名单 (登出吊销)
    +
Spring Security @PreAuthorize (4角色 RBAC)
    +
MyBatis-Plus 参数化查询 (零 SQL 注入)
    +
Element Plus 默认 XSS 转义
    =
全链路安全覆盖
```

### 3.3 事件驱动

使用 **EventOutbox 模式** 实现可靠事件投递：

- 业务操作 + 事件写入在 **同一事务**
- 定时任务扫描 PENDING 事件
- 失败自动重试（retryCount ≤ 3）
- 保证告警→通知不丢失

### 3.4 数据库设计

- **UUID v4 主键**：分布式友好
- **乐观锁**：MyBatis-Plus @Version
- **逻辑删除**：@TableLogic
- **枚举约束**：13 组 CHECK 约束
- **版本迁移**：V1.3 → V1.4 增量 SQL

## 四、经验与反思

### 4.1 做得好的

| 方面 | 说明 |
|------|------|
| **先设计后编码** | PRD → 原型 → 架构 → 类图 → 数据库 → API → 编码，顺序不乱 |
| **微服务演进** | device-collector 独立部署 + RabbitMQ + Nacos 服务注册，为后续扩展打好基础 |
| **DDD 坚持到底** | 没有因为"单人开发"就放弃分层，Domain 层始终保持零框架依赖 |
| **AI 辅助效率** | Hermes 集群自动代码审查、任务拆解，节省约 40% 调试时间 |
| **安全早规划** | 从第一天就用 BCrypt + JWT，没有"先明文后加密"的返工 |
| **数据库设计一次到位** | ER 图先行，18 张表后续无返工 |

### 4.2 可以改进的

| 方面 | 反思 | 改进方向 |
|------|------|---------|
| **前端测试缺失** | 过于依赖手动验证 | 引入 Playwright E2E |
| **部分模块测试不足** | CRUD 模块缺单元测试 | 即使简单也要写，养成习惯 |
| **文档与编码并行不够** | 文档集中在后期补 | 下次边做边写 |
| **Git 提交粒度** | 部分提交过大 | 坚持一个功能一个 commit |
| **WSL2 跨文件系统** | I/O 慢 10-50 倍 | 项目放 WSL 原生文件系统 |

### 4.3 AI 辅助开发的得失

**得：**
- QA Agent 在 75 个任务中发现 4 个真实 bug，人工审查可能遗漏
- DBA Agent 审查了全部 18 张表索引，给出专业建议
- 架构师快速完成技术选型对比，节省调研时间
- Leader 自动拆解子任务，保持开发节奏

**失：**
- AI 有"顺着话说"的倾向，需要多模型交叉验证
- Agent 偶尔越权操作（创建任务到错误 board），需固化规则
- Cron 调度器在 WSL2 高负载下偶发冻结，需手动重启
- AI 生成代码有时过度设计，需人工裁剪

## 八、结语

作为软件工程专业的毕业设计，本项目展示了 **系统设计能力、全栈开发能力、工程质量意识、以及利用 AI 提效的工程思维**，达到了预期的全部目标。
